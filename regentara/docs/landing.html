MVP · Workflow Runner

Regentara

A governed loop that coordinates provider CLI agents — Producer, Reviewer, and Remediator — and delegates the “is this good enough?” decision to an injectable policy.

regentara --task-file tasks/accepted-task.md regentara --debug --task-file …

The core idea

Regentara does not decide whether a result is good enough by itself. It runs agents, validates their structured outputs, records run progress, and delegates the post-review routing decision to a ReviewFixPolicy.

Workflow loop

Each workflow starts from a task file and proceeds through the same loop.

  1. Producer receives the current task and returns a structured completion claim.
  2. Reviewer receives the task plus producer output and returns a structured verdict.
  3. ReviewFixPolicy.decide receives the verdict plus its opaque session state and returns one of complete-ok, complete-fail, or remediate.
  4. Remediator (on remediate) receives the task, producer output, latest reviewer verdict, and completed review history, then returns a new task.
  5. Repeat with the remediated task until the policy returns a terminal decision.

Components

Four roles, three of them provider CLI agents and one routing seam.

Agent

Producer

Provider CLI agent. Reads the task, performs work, returns an artifact validated against regentara://schemas/producer-output.

Agent

Reviewer

Provider CLI agent. Reads task plus producer output, returns a verdict validated against regentara://schemas/reviewer-output.

Policy

ReviewFixPolicy

Routing seam between review output and workflow control. Owns budget, escalation, severity mapping, convergence, and cross-round state.

Agent

Remediator

Provider CLI agent. Reads task, producer output, latest verdict, and review history, returns a new task validated against regentara://schemas/remediator-output.

Runtime

Orchestrator

Drives the loop, validates structured outputs, threads opaque policy session, and emits operational progress events.

Runtime

Provider CLI Executor

Spawns the selected runner (claude-code, codex) in native structured-output mode. Treats stdout/stderr as diagnostics.

The policy seam

The interface is intentionally small. Regentara threads the returned session into the next call but does not inspect it. 

const reviewFixPolicy = {
  decide: async ({ session, verdict }) => {
    if (verdict.verdict === "accepted") {
      return { decision: "complete-ok", session };
    }

    return { decision: "complete-fail", session };
  },
};

Production composition uses ConfigBasedReviewFixPolicy from policy.yaml by default. Embedding callers can override with createRegentaraComposition({ reviewFixPolicy }).

Boundaries

Regentara is intentionally narrow. Knowing what it does not own is part of the design.

Regentara does

  • Invoke provider CLIs as subprocesses
  • Validate structured agent outputs against JSON Schema
  • Drive the Producer → Reviewer → Policy → Remediator loop
  • Resolve provider/model tiers from models.yaml
  • Append events to runs/<run-id>/events.jsonl
  • Fail fast on startup or runtime errors

Regentara does NOT

  • Call provider APIs directly
  • Manage credentials, sessions, or auth state
  • Manage worktrees, branches, commits, or PRs
  • Run builds, tests, formatting, or installs
  • Sandbox, cleanup, retry, or impose timeouts
  • Decide if a result is “good enough” — the policy does

Provider CLI execution

Each agent prompt and expected JSON Schema is passed to the runner’s native structured-output mode. Stdout and stderr are diagnostics; the loop consumes only the validated semantic JSON.

Runner

claude-code

claude -p --model ... --output-format json --json-schema ...
Runner

codex

codex exec --model ... --config model_reasoning_effort=... --output-schema ... --output-last-message ...

Debug mode

--debug prints compact live progress lines to stderr without changing stdout, exit codes, run metadata, or events.jsonl. It is a read-only observability layer over the same loop. 

regentara --debug --task-file tasks/accepted-task.md
Route label

Single line per agent

Selected runner/provider/model/tier is reported as one compact label, e.g. codex/openai/gpt-5.5/high.

Cost & duration

Per-agent diagnostics

When a provider exposes cost or duration, debug output includes the compact per-agent figures alongside the route label.

Failure classification

Inferred from diagnostics

Runtime failure debug lines include a short provider error classification when Regentara can infer one from provider stdout/stderr.

Runs & observability

Each run appends operational progress events to a per-run JSONL log. Authored artifacts are never rewritten to record progress. 

latest_run="$(ls -td "$HOME"/.regentara/runs/* | head -n 1)"
tail -f "$latest_run/events.jsonl"

The watched event surface includes run ID, current agent, selected provider/model tier, Producer task file, current policy decision, runtime failure reason, final status, runner/session references, and provider stdout/stderr diagnostics.
