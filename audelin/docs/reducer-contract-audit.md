# Audelin reducer contract audit

LAB-856 · 2026-11-03 · source snapshot `57163a75`

The audit covers every reducer in `macos/Sources`: six named `*Reducer`
implementations plus `PanelPresence.reduce`. Tests were read in both the component
package and `macos/App/Tests`. These are final implementations, not scaffolding.
The assessment applies the project's state-machine contract: all state fields and
nested payloads must be publicly constructible; rendered values belong in stored
state; pure formatting dependencies are injected and spy-tested; reducer tests
use `make*` given-state factories and expected mutation closures, with no closure
for no change and no `@testable`. Async reducer cases have matching `delivers:`
effect assertions; handler/doer tests control collaborators through spies.

**Verdict: each of the seven machines needs a fix.** Several already satisfy the
production-state rules and need only the required test form. This audit does not
change runtime behavior. Each row gives the evidence, the concrete correction,
and the existing coverage to preserve in its separate fix issue.

The inventory was cross-checked by searching all source files for reducers and
transition functions. `MicrophoneCapture/DeviceFollowing.transition` is internal
adapter bookkeeping, not a composed machine; the state-machine contract does not
turn it into one. UI payload types and adapter snapshots without reducers are
also outside this audit. Composer-only formatting is not silently assigned to
these fixes.

Recent history was checked for affected modules. Reading's final-prefix,
incremental-layout and equality changes make its performance and cursor tests
especially important; MenuBar's reopen fixes make explicit reopen/delay states
important. The fix issues retain these existing seams and behavior tests. The
audit itself is documentation only: validation consists of a complete inventory,
source/test evidence checks, matching sub-issues and a clean diff; no Swift test
run is claimed.
