# Fill in — QA

Driven through fakes of its own interfaces: a written track that grows on
cue, holds a read on cue and can fail one; a live text that turns each
numbered word-tone into a known word, can be held loading and can fail
getting ready or hearing a given word; and a live-audio position set on cue, which can be marked
ended. A word comes back only if its tone was written.

## S-1 Getting ready, then reading from the start

Ten words written while live text is held loading, the position at the
tenth; on release all ten come back, in order. Evidence: Missing.

## S-2 Switched on, it fills in from the start

Five words written with live text off; filling in after a switch on
brings all five back, each marked written later. Evidence: Missing.

## S-3 Audio ending while getting ready is read to its end

Words written and the audio marked ended while loading is held; on
release every written word comes back. Evidence: Missing.

## S-4 Audio ending while catching up is read to its end

A read held mid catch-up, more words written and the audio marked ended;
on release every written word comes back, none twice. Evidence: Missing.

## S-5 Abandoned while getting ready

Abandoned while loading is held: it reads as ended with no text while the
load is still held. Evidence: Missing.

## S-6 Abandoned while catching up

Abandoned while a read is held after the first words came back: it reads
as ended with those words, the read still held. Evidence: Missing.

## S-7 Failing to get ready

The fake fails getting ready: it reads as failed. Evidence: Missing.

## S-8 Failing to read the written track

A read fails after the first words came back: it reads as failed with
those words kept. Evidence: Missing.

## S-9 Live text failing while catching up

Three words written; the fake hears the first and fails on the second: it
reads as failed with the first word kept. Evidence: Missing.
