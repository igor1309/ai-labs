# AGENTS (audelin)

Issues are in the Multica project `Audelin`, in the `ai-labs` workspace.

- The component diagram is `docs/live-text.drawio`, generated by `scripts/component-diagram.py`
  from `macos/Package.swift` and `macos/App/Package.swift`. Any step that adds a target or changes a dependency reruns it in
  the same commit; a new target needs its lane and line in the script's `TARGETS`, and the
  script stops until it has one.
- Tests do file and process work directly; they do not hop it to a queue. Cleanup is awaited
  with `withCleanup { } cleanup:`, children run through `exitStatus(of:)`, and audio files are
  read with `audioFile(_:)`. Core Audio listener callbacks stay on Core Audio's threads.
- A change meant to make the text path faster is judged by `macos/Benchmarks` (its README):
  median instructions per word against the saved `base`, not by unit or count tests.

- The app and rehearsal compose machines in `macos/App/Sources/Composer`; components stay in
  `macos/Sources`. Build and test both packages from their directories with
  `swift build --build-tests`, then run the tests through `scripts/swift-test-bounded.sh <seconds>`,
  never bare `swift test`: the runner kills a run past its time or memory cap, where a runaway
  test would otherwise exhaust the Mac. `scripts/gate-step.sh` gates both and bundles.

## Design

- The whole Audelin design is one file, `docs/design/visual-language.pen`:
  the Glass Ledger tokens, every component and every screen. Draw new
  screens and states in it; do not start another `.pen` for a feature, not
  even for drafts.
- Its variables are the only token source. Build from its components; a
  new part goes on a components board in that file. `docs/design/tokens.json`
  is a snapshot of those variables and changes with them (steps in
  `docs/design/README.md`).
- Each feature keeps a brief, a Markdown file beside it in `docs/design/`,
  and a row in the README's frame index saying where its frames sit.
- `docs/research/gallery/` holds research boards of other apps, not design.

## Real-audio tests

- Four test files use the Mac's audio hardware through `coreaudiod`: the call-audio probe, the
  Core Audio binding, the microphone binding and the end-to-end recording test. CI skips them
  (`GITHUB_ACTIONS=1`); locally they run with every `swift test`.
- When one fails, do not rerun it to diagnose. Each run opens real audio connections, and a
  failed or hung run can leave them behind; repeated runs grew `coreaudiod` to about 50 GB and
  froze the Mac until a hard reboot.
- On a failure, check `coreaudiod` first: its memory (`ps -Ao rss,command | grep coreaudiod`)
  and its connections from dead processes (`pmset -g assertions`). If it holds either, stop
  every audio run, tell the owner it needs restarting, and gate with `GITHUB_ACTIONS=1` until
  it is.
- To verify these tests, run each file once, on its own, and check `coreaudiod`'s memory after
  each. Stop at the first sign it grows.

## Live tests

- Live tests drive the running app through accessibility; what each proves and how to run it
  is in `macos/scripts/live/README.md`. They need a logged-in session, so run them locally.
- Run `sh macos/scripts/live-calls-merge.sh` when merging, the calls list or calls storage
  changes, `sh macos/scripts/live-calls-tags.sh` when call tags change, and `sh macos/scripts/live-calls-summary.sh` when making notes or the calls window
  changes. Each prints `PASS:` only when every scenario passed.
- `sh macos/scripts/live-browser-names.sh` rehearses a one-minute call twice,
  once with recorded Telemost extension events replayed through the app's socket
  (`AudelinRehearsal --browser-events FILE`) and once without. It reads the panel
  rows through Accessibility and checks that the two remote speakers are named on
  their rows and in `transcript.md` only with the events. Screenshots go to the
  folder it prints under `$TMPDIR`. It runs nightly on the self-hosted Mac.

## Profiling

Profile: from `audelin/macos`, `scripts/profile-rehearsal.sh capture --capture-after 120 --capture-for 30 --minutes 20 --speed 1`
records only that wall-clock window and summarizes CPU, hangs and signpost intervals in `macos/profiles/`.
Endurance: `scripts/profile-rehearsal.sh endurance --minutes 180 --speed 1` runs without Instruments and keeps only the rehearsal report.
Recognisers are fakes: lag is pipeline backlog, and speeds above 1× measure saturation.
Recurring real-model baselines and weekly artifact review: [profiling runbook](docs/research/recurring-profiling.md).

Optimized load tests: from each of `audelin/macos` and `audelin/macos/App`, run `swift build --build-tests -Xswiftc -O`,
then, in the same directory, run `../scripts/swift-test-bounded.sh 120 -Xswiftc -O --filter LoadTests` or `../../scripts/swift-test-bounded.sh 120 -Xswiftc -O --filter LoadTests`, respectively.

`python3 -I audelin/scripts/slow-tests.py` runs the tests of all three
packages three times, serially, and writes every test, ranked by its median duration
with its file and line, to `slow-tests-report.json` and `.md` in the current
directory. The weekly `audelin-slow-tests` workflow runs it on macOS and
hands the ranking to the slow-test hunter autopilot. Tests listed in
`scripts/slow-tests.skip` (one test id per line, `#` for the reason) are
marked as skipped there. It runs `swift test --no-parallel`, since in a parallel
run a main-actor test's duration includes its wait for the main actor.

## Self-hosted runner

- **Signing on the runner** uses the owner's Apple Development certificate, so macOS
  keeps the microphone and audio-capture grants across builds. The runner's launch
  agent (`~/Library/LaunchAgents/actions.runner.igor1309-ai-labs.MacBook-Pro.plist`)
  must not set `SessionCreate`: with it, jobs run in a security session that cannot
  reach the login keychain and `codesign` fails with `errSecInternalComponent`.
  Reinstalling the runner with `svc.sh install` adds it back; remove it with
  `/usr/libexec/PlistBuddy -c "Delete :SessionCreate" <plist>` and reload the agent.
