# Reinix Name Brief

## Name

**Reinix**

## Product Frame

Reinix is an orchestration harness for executing verifiable tasks through capable agents until an acceptable outcome is reached.

It is not primarily a coding agent, reviewer, workflow engine, or chat assistant. It is the control layer that holds direction, constrains execution, and coordinates stronger downstream agents.

## Rationale

**Reinix** is built around the idea of **reins**: control, guidance, restraint, and directed movement.

That maps well to the product:

- agents may be powerful, but they need direction;
- execution must stay bounded by task intent;
- outcomes must be driven toward verification, not merely generation;
- the harness is less about being intelligent itself and more about controlling intelligent executors.

The name avoids overfitting to current implementation details such as review loops, verdicts, remediation, or policy routing. Those may remain important mechanisms, but they should not define the parent product name.

## Why It Fits

**Reinix** signals:

- controlled agent execution;
- disciplined delegation;
- orchestration without orchestral cliché;
- harnessing capability rather than replacing it;
- practical infrastructure rather than consumer AI branding.

It works better than names centered on “verdict” or “review” because the durable product promise is broader than adjudication. Verification is part of the execution model, but not necessarily the brand center.

## Tradeoffs

The `-ix` ending gives the name CLI/tooling sharpness, but carries some dated tech/pharma-brand residue.

This is acceptable because the root does the primary semantic work:

> Reinix holds the reins over capable agents.

The name is not perfect, but it is compact, memorable, technically usable, and aligned with the product’s broader scope.

## Positioning Sentence

**Reinix is a control harness for running verifiable tasks through agent teams.**

## Verdict

**Reinix** is a strong candidate for the parent orchestrator name because it names the durable control relationship rather than a temporary or internal execution mechanism.
