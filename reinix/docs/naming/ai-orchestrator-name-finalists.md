# AI Orchestrator Name Finalists

## Product naming target

The name should fit a CLI-first agent orchestration product whose core identity is a governed coding-agent loop:

- producer generates work
- reviewer returns a structured verdict
- policy decides whether to accept, retry, remediate, or escalate
- remediator fixes issues and feeds the loop

The name should feel serious, compact, CLI-friendly, and suitable for a control layer above smarter agents.

## Availability standard

Availability is treated as a practical risk filter, not the main ranking axis.

A name is only a hard concern if it collides with agent orchestration, coding agents, LLM workflow tooling, eval/review systems, or adjacent developer infrastructure.

Unrelated historical software, small repos, personal handles, unrelated consumer products, and non-adjacent businesses are soft noise rather than blockers.

## Finalists

## 1. Verdix

### Fit

**Verdix** is built around **verdict**, which is the central hinge of the product loop. The reviewer produces a verdict, and the policy layer routes the next step based on that verdict.

### Strengths

- Strongest semantic fit for the review-driven loop.
- Short, punchy, and CLI-friendly.
- Easy to type and easy to say.
- Immediately suggests judgment, decision, and adjudication.
- Better than a general governance name because it points to the actual operating mechanism.

### Weaknesses

- Less expressive of the harness/control aspect than Reinix.
- Some real-world usage exists, including software/product contexts, so it is not pristine.
- Can sound slightly legalistic if over-positioned around verdicts.

### Assessment

**Verdix** is the strongest product-mechanism name. It gives the clearest explanation of what drives the loop.

### Role in final set

Primary candidate.

---

## 2. Reinix

### Fit

**Reinix** is built around **reins**, which fits the harness/control side of the product. It suggests a compact control layer that directs stronger agents without claiming to be the intelligence itself.

### Strengths

- Strongest harness/control candidate.
- Clean CLI feel.
- Good typing shape.
- More original-feeling than Verdix.
- Avoids review/legal overtones.
- Fits the original “harness / whip / commands smarter agents” framing.

### Weaknesses

- Does not surface verdict, review, or remediation directly.
- More abstract than Verdix; needs positioning to connect it to the loop.
- The “rein” root may be understood by some users, but not all.

### Assessment

**Reinix** is the best name if the product is framed primarily as an agent-control harness rather than a verdict-driven review loop.

### Role in final set

Best alternative candidate.

---

## 3. Veridix

### Fit

**Veridix** blends associations around **verity**, **verification**, and **verdict**. It is close to Verdix, but slightly more distinctive and less literal.

### Strengths

- Keeps the judgment/truth/review field.
- More distinctive than Verdix.
- Still compact and CLI-friendly.
- Has a technical product feel.
- Avoids being a plain verdict-derived name.

### Weaknesses

- Less immediately legible than Verdix.
- Slightly more synthetic.
- May need explanation on first encounter.
- The added syllable/lettering slightly reduces punch.

### Assessment

**Veridix** is a strong fallback if Verdix feels too exposed, too occupied, or too directly tied to “verdict.”

### Role in final set

Distinctive fallback.

# Recommendation

## Best overall

**Verdix**

It most directly names the decisive element of the system: the structured verdict that drives policy routing and remediation.

## Best control/harness alternative

**Reinix**

It is strongest if the product identity should emphasize control over agents rather than review verdicts.

## Best fallback if Verdix feels too occupied

**Veridix**

It preserves the judgment/review field while being more distinctive and slightly less literal.

# Current ranking

1. **Verdix**
2. **Reinix**
3. **Veridix**
