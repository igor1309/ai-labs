# Fix PR Template

The agent uses a single stable PR for all sync runs. Title and body shape below are mandatory; the agent does not invent alternative formats.

## Branch

`dashboard-sync/daily` — fixed, never renamed. The agent force-updates this branch on every run that produces drift; on a run where all surfaces are clean, the agent does not touch the branch and does not open or update a PR.

## Title

```
[dashboard-sync] daily sync — <YYYY-MM-DD>
```

`<YYYY-MM-DD>` is the run-completion UTC date. Example: `[dashboard-sync] daily sync — 2026-05-10`.

The `[dashboard-sync]` prefix is mandatory for `gh pr list` filtering and parallels `doc-drift-agent`'s `[doc-drift]` convention.

## Body

The PR body is rendered directly from the sync report (per `report-format.md`) plus a fixed footer. Structure:

```
<sync report top-level shape: header, per-surface status, candidates,
 removed, unmapped types, errors — see report-format.md>

---

**Do not auto-merge.** This PR was generated by `dashboard-sync-agent`.
The agent never merges or approves PRs. Auto-merge is forbidden by ADR
v0.0.1.

The agent regenerates `docs/products.html` cards from the root README's
`## Components` table on every run; manual edits to that file are not
preserved. Maintainer-authored content for product cards lives in the
Components row, not in the HTML.

Untracked candidates above are top-level directories present in the repo
but absent from both `## Components` and `## Structure`. The agent does
not silently classify them — the maintainer either adds the appropriate
table row or extends the excluded-directories list in
`dashboard-sync-agent/agent/project-registry.md`.

Removed-directory drift indicates a registry row whose directory no
longer exists. Resolve by removing the row from the README.

Source: `dashboard-sync-agent/agent/agent.md` v<version> on
<workspace> at <commit>.
```

The `<version>` token is the version line from the front matter of `agent.md`. The `<commit>` token is the trunk commit the agent ran against (recorded by the cron wrapper before invocation).

## Mechanics

Pass the title and body to `gh` via a file — never via an inline heredoc or `$(cat <<'EOF' … )` command substitution. The body is multi-line Markdown with tables, backticks, and `$`-like tokens; when assigned to a shell variable through the tool layer the heredoc collapses to a single line, never terminates, and the command fails. A failed `body=$(cat <<'EOF' … )` line in the run report is the signature of this anti-pattern; if you produce one, switch to `--body-file`.

Instead:

1. Render the body and write it to a temp file with the `write` tool (for example `/tmp/dashboard-sync-pr-body.md`).
2. Create or update the PR with `--body-file`:
   - New PR: `gh pr create --repo igor1309/ai-labs --head dashboard-sync/daily --base trunk --title "<title>" --body-file /tmp/dashboard-sync-pr-body.md`
   - Existing PR: `gh pr edit <number> --repo igor1309/ai-labs --title "<title>" --body-file /tmp/dashboard-sync-pr-body.md`

## Update behavior

- **Drifted run, no existing open PR on the stable branch.** The agent resets the branch to `trunk`, applies changes, pushes, and opens a new PR with the title and body above.
- **Drifted run, existing open PR on the stable branch.** The agent force-pushes the new commits (`git push --force-with-lease origin dashboard-sync/daily`) and updates the PR body to reflect the current run's report. The PR title is updated to the current date. PR comments and reviews on the previous run's body are not preserved by GitHub when the body is rewritten — this is acceptable; reviewers comment on the diff, which the agent does not modify destructively if the next run produces the same drift.
- **Clean run.** The agent does not touch the branch or the PR. Existing open PRs (if any) remain as-is — they represent un-reviewed prior drift, not current drift.
- **PR closed by maintainer without merging.** The agent treats the next drifted run as "no existing open PR" and opens a fresh PR. The agent does not reopen closed PRs.
- **PR merged.** The branch is deleted by the merge (per repo convention `--auto --delete-branch`). The next drifted run reinitializes the branch from `trunk`.

## Idempotence

If the rendered body and title equal the current PR's body and title, the agent skips the update API call entirely. The agent does not refresh-for-the-sake-of-refreshing — only meaningful change triggers a write.

## Anti-patterns

- Multiple branches (e.g. `dashboard-sync/<slug>`) per finding. Wrong — sync changes are batched into one PR per run.
- Per-surface PRs. Wrong — one PR covers all three surfaces.
- New PR on every run. Wrong — re-uses the stable branch.
- Editing the PR body to add `LGTM` or `looks good` style commentary. Wrong — the body is the report; opinions and reviews go in PR comments by humans.
