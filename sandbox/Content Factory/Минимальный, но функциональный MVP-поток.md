## Минимальный, но функциональный MVP-поток

```
Заказ  →  Сценарий  →  Сборка  →  QC & Publish
│↑           │↑           │↑
│└─ human-gate 1 ─┘   │└─ human-gate 2 ─┘
└─ human-gate 0 ───────────────────────┘
```

### 1. Критические агенты (ядро MVP)

| Этап | Агент / сервис | Главная ответственность | Точка обязательного человека |
|------|----------------|-------------------------|------------------------------|
| **Заказ** | **Агент управления заказами** — приём брифов, валидация параметров (тема, длительность, формат, целевое качество), постановка в очередь  [oai_citation:0‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW) | Проверка корректности брифа, ручная правка при необходимости |
| **Сценарий** | **Агент создания сценариев** — генерация 1-3 вариантов сценария под заданные параметры, авто-оценка «читабельность + тема»  [oai_citation:1‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW) | Одобрение/редактирование финального варианта |
| **Сборка** | **Агент сборки видео** — компоновка визуала, озвучка, базовый стиль, адаптация под вертикаль/горизонталь  [oai_citation:2‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW) | Предпросмотр и, при необходимости, запрос пересборки |
| **QC & Publish** | **Система управления качеством** — автоматические тех-чек-листы (разрешение, битрейт и т.д.) + контент-фильтры; ручное «финальное ОК» → публикация на 1 выбранную платформу  [oai_citation:3‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW) | Финальное «Да / правим» перед публикацией |

| Слой | Что делает | Почему в MVP |

| **Универсальный ИИ-адаптер** | Единый интерфейс к LLM/ген-моделям, кэш, мониторинг лимитов, авто-переключение провайдера при сбоях  [oai_citation:4‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW) | Позволяет сразу закладывать принцип заменяемости, избегая жёсткой привязки |
| **Мониторинг затрат и метрик** | Трек расходов по агентам, базовые KPI: стоимость ролика, % успешных заказов, % одобренных сценариев, engagement роликов  [oai_citation:5‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW) | Раннее понимание экономической эффективности и точек узкого горлышка |

### 3. Контрольные метрики для запуска (Stage 1 «1-4 ролика/неделю»)

- **Время цикла** (бронза ≤ 24 ч)  
- **% одобрения сценариев** (≥ 70 %)  
- **% роликов, прошедших QC с первой попытки** (≥ 60 %)  
- **Стоимость ролика** — бенчмарк для дальнейшей оптимизации  [oai_citation:6‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW)  

### 4. Принципы, заложенные в архитектуру

1. **Заменяемость моделей**: все вызовы идут через адаптер → легко менять GPT-4 ↔ Gemini Pro и т.д.  [oai_citation:7‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW)  
2. **Постепенная автоматизация**: на каждом этапе стоит human-gate, который можно убирать после валидации качества  [oai_citation:8‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW)  
3. **Graceful degradation**: при недоступности модели — авто-переключение или постановка заказа в очередь, без стоп-кадра для всей фабрики  [oai_citation:9‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW)  
4. **Чёткая трассировка затрат** ещё в MVP — база для расчёта ROI и решения «куда инвестировать автоматизацию»  [oai_citation:10‡Архитектура Контент-Фабрики Практичный MVP с Постепенным.md](file-service://file-41wb39PGMM8DJZwkfVD7gW)  

### 5. Как выглядят первые шаги запуска

| Шаг | Действие | Цель |
|-----|----------|------|
| **0. Настройка** | Подключить 1 LLM для сценариев + 1 API генерации/редактирования видео; задать лимит расходов | Старт без избыточных интеграций |
| **1. Пилотный заказ** | Оператор вручную создаёт бриф → прогон по цепочке → публикация | Проверить сквозной поток end-to-end |
| **2. Итерация** | Собрать метрики, вручную разобрать ошибки, подкрутить промпты/шаблоны | Подтвердить воспроизводимость качества |
| **3. Расширение** | Включить очередь заказов (до 4 в неделю), добавить ранжирование по приоритету | Увидеть стабильность при маленьком параллелизме |
| **4. Решение о следующем этапе** | На основе KPI и расходов решить — автоматизируем QC или добавляем агент тренд-анализа | Осознанное масштабирование, а не «сразу всё» |

---

**Итого:** MVP требует всего четырёх главных агентов + 2 сервисных слоя, трёх ручных «точек контроля» и набора базовых метрик. Такой минимальный каркас уже создаёт воспроизводимый контент-поток, а все дальнейшие улучшения (тренд-сканер, художественный стиль, мультиплатформенная дистрибуция) подключаются модульно без перестройки ядра.
