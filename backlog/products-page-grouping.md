# Backlog — products page grouping

The group headings on [`docs/products.html`](../docs/products.html) have drifted into
awkward buckets. In particular **"Frameworks & Concepts"** lumps together unrelated
things — `neris` (a Swift framework), `niora` (a design concept), and now `cairana`
(an early-stage future product). A framework, a concept, and a research-stage product
do not belong under one label.

## Task

Rethink the grouping taxonomy for the products page.

- Decide the dimension that groups well — maturity (shipped / building / research),
  surface type (web app / CLI / MCP / service), or audience — rather than the current
  mix of the two.
- Consider a dedicated **"Research / Early-stage"** or **"Future products"** group so
  concept- and naming-stage entries (`niora`, `cairana`) aren't filed next to a
  shipped framework.
- Keep it consistent with the README Components table types so the two surfaces don't
  diverge.
- Note: `docs/products.html` is regenerated by the dashboard-sync-agent — any taxonomy
  change must be reflected in that agent's generation logic, not just hand-edited.

## Open questions

- Should the grouping be derived automatically from the README Components `Type`
  column to keep a single source of truth?
