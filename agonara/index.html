Agonara

An API-first structured learning program environment you run as your own private instance — curated programs, progression, evidence of mastery, and agent-ready backend contracts.

From the ancient Greek agon — exercise, trial, disciplined striving. Curators assemble programs from trusted sources; learners move through them with clear sequence, checkpoints, and evidence of understanding. AI assists, but does not own the curriculum.

What you do with it

Curate programs, learn, prove mastery

Agonara is a working product loop, not a framework. Curators build a trusted program, learners progress through it, and assessment produces owner-only evidence of mastery — with AI assisting curation and evaluation without ever owning the curriculum.

Step 1 · Curator

Assemble a program

Research trusted sources, draft topics, concepts, materials, and checks, then explicitly accept them into the program corpus. LLM suggestions and coverage-gap diagnostics assist, but stay draft until accepted.

Step 2 · Student

Join and progress

Learners join a program and move through accepted topics, concepts, and materials in clear sequence inside the /learn UI — never mutating the corpus they study.

Step 3 · Assessment

Check understanding

Quick Checks, open-answer attempts, and readiness checks run against accepted criteria. Open answers are evaluated by a worker behind a provider boundary; results are recorded as evidence.

Step 4 · Mastery

See evidence of mastery

Learner-state interpretation turns attempts into owner-only progress and weak-area summaries with supporting evidence — readable only by the learner who owns them.

Getting started

Run your own private instance

Agonara is built to be self-hosted: a small, recoverable backend that runs the same in a container on a VPS or home server as it does locally for development. A fresh instance is inert until you bootstrap the first Admin. (See full walkthroughs in docs/demos.md.)

1

Build & run the container

Docker Compose builds the backend + UI image and runs it with persistent SQLite state. The container refuses to start without an operator bootstrap secret.

AGONARA_BOOTSTRAP_SECRET=operator-secret \ docker compose -f agonara/compose.yaml up --build
2

Bootstrap the first Admin

The instance becomes operational only after the first-Admin bootstrap establishes an active Admin identity. Secrets are read from JSON stdin, never from CLI arguments.

printf '%s' '{"bootstrapSecret":"operator-secret","password":"…"}' \ | node agonara/src/cli.js identity bootstrap-admin \ --login admin@example.test --stdin-json --json
3

Open the boards

Sign in as Admin to run operations, then hand Curators and Students the /learn product UI. Both surfaces are clients of the same backend contracts.

http://127.0.0.1:18080/admin http://127.0.0.1:18080/learn
4

Create a program & invite people

Create a program, accept corpus from trusted sources, and invite Students. From there the product loop above takes over — learners progress and accrue evidence of mastery.

Current implementation snapshot

What is implemented today

Backend, domain, and product surfaces shipped as vertical slices. Each slice carries storage, domain commands, session-backed HTTP routes, backup/restore, and — where noted — a /learn product UI.

Identity & Operations

First-Admin bootstrap, local-password login, server-side sessions, Admin identity ops, audit reads, health, diagnostics, request correlation, completion logs, backup & restore.

Program Shell & Membership

Program creation, Student self-join/leave/rejoin, invitation lifecycle, participant listing, Student removal, curator leave, Admin exceptional recovery/revocation, effective-participation checks, event reads.

Corpus Curation

Program sources, corpus candidates, acceptance/rejection, accepted corpus revisions, corpus event reads, and backup/restore support.

Topic / Concept / Material Navigation

Accepted topics, concepts, definitions, principles, material references, relationships, historical revisions, curator candidate routes, student-safe traversal, and a /learn navigation UI.

Accepted Checks & Criteria

Assessment criteria, open-answer checks, accepted revisions, and curator / student / admin read separation.

Open-Answer Workspace

Student submission, idempotency, owner-only attempt detail/list reads, evaluation status/evidence reads, evaluator orchestration, worker execution, and backup/restore support.

Quick Check

Session-backed routes, candidates, accepted revisions, protected answer keys, student-safe delivery projections, immutable attempts, matched evidence, and a /learn Curator/Student UI.

Learner-State Interpretation

Explicit target-link curation metadata, read-time owner-only progress and weak-area summaries, supporting-evidence target detail, and a /learn learner-state UI.

Readiness Checks

Topic- or named-period readiness definitions, evidence-backed explicit Student readiness attempts, idempotent retry, owner-only attempt reads, and a /learn readiness UI.

Coverage Gaps

Read-only Curator Workspace diagnostics over accepted corpus, deterministic draft_guidance reports, protected redaction, and a /learn filtering / drill-down UI.

LLM-Assisted Suggestions

Curator Workspace-owned deterministic-provider slice for redacted draft suggestions, origin inspection, accept/reject review, draft materialization without accepted-corpus promotion, and a /learn review UI.

Admin Board

A local operations board for bootstrap, sign in/out, Identity management, operational access inspection, audit inspection, and exceptional membership recovery/revocation.

Deferred: recommendation ranking and persisted mastery models still need separate specs; student- and curator-facing product UI beyond the shipped /learn slices is not yet implemented.
