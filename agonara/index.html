What you do with it

Turn scattered study into a path you can follow

Serious learning breaks down when materials, concepts, and proof of understanding live in separate piles. Agonara gives you a program-shaped workspace for turning that scatter into a path you can follow, revise, and verify.

Curate

Build from selected sources

Shape sources into a program, connect concepts to materials, define checks, and accept what belongs.

Follow

Learn through a program

Follow selected materials, concepts, checks, and feedback without losing the thread.

Verify

Turn answers into feedback

Move through checks and feedback so progress stays grounded in evidence that belongs to the learner.

Structure

Keep progress durable

Sources are shaped into a program, concepts connect to materials, checks turn answers into feedback, and progress stays grounded in learner-owned evidence.

BYOA

Bring the agent you already use

Point it at your Agonara instance and follow role-specific guidance for curating programs, learning through them, and managing the private instance. The agent helps with the workflow. You remain responsible for accepted program content and how learning evidence is used.

Agents can help draft, evaluate, and carry out the workflow, but accepted program content remains a human decision.

Operator skills

Role-specific guidance

The implemented skills are role-scoped operating manuals for agents using an Agonara instance through the published API contract. Shared foundations handle connection and participation; role skills keep curator, student, and admin jobs separate.

Foundations

Loaded by every role before the agent performs a job against an instance.

agonara-api-access
Health, password login, the agonara_session cookie, CSRF, idempotency keys, and response envelopes.
agonara-membership
Role-neutral participation, invitations, effective participation, and membership history.

Curator Work

A job bucket for building, grounding, assessing, and operating program participation.

agonara-curator-corpus
Create programs and move topics, concepts, materials, and navigation from draft candidates to accepted corpus.
agonara-curator-assessment
Author open-answer, quick, and readiness checks while keeping answer keys curator-only.
agonara-curator-research
Record sources, read coverage gaps, and review LLM-assisted suggestions as draft material.
agonara-curator-participation
Manage admission policy, invitations, participants, student removal, and curator leave.

Role Operations

Single-role operating surfaces for learning and private-instance administration.

agonara-student
Discover, join, study, answer checks, and read feedback using only accepted corpus and the student's own state.
agonara-admin
Bootstrap and operate a private instance: identities, credentials, Admin authority, audit, access, and exceptional recovery.

Getting started

Operate a private instance

Agonara is built for private, recoverable operation. Bootstrap an instance, manage identities and access, inspect audit events, and preserve program and learner state through backup and restore. The dockerized private self-hosted shape is the committed operational boundary, accepted in ADR-017 (see Architecture → Deployment). A fresh instance is inert until you bootstrap the first Admin. (See full walkthroughs in docs/demos.md.)

Node.js 22 better-sqlite3 ^11.8 API-first HTTP backend CSRF protection Request correlation Operator CLI Docker + Compose Backup / restore
1

Build & run the container

Docker Compose builds the backend + UI image and runs it with persistent SQLite state. The container refuses to start without an operator bootstrap secret.

AGONARA_BOOTSTRAP_SECRET=operator-secret \ docker compose -f agonara/compose.yaml up --build
2

Bootstrap the first Admin

The instance becomes operational only after the first-Admin bootstrap establishes an active Admin identity. Secrets are read from JSON stdin, never from CLI arguments.

printf '%s' '{"bootstrapSecret":"operator-secret","password":"…"}' \ | node agonara/src/cli.js identity bootstrap-admin \ --login admin@example.test --stdin-json --json
3

Open the boards or load a skill

Use BYOA by loading the role skill for the job and pointing your agent at the instance URL. The /admin and /learn boards remain available browser clients of the same contracts.

http://127.0.0.1:18080/admin http://127.0.0.1:18080/learn
4

Create a program & invite people

Use the curator skills or /learn to create a program, accept corpus from trusted sources, and invite Students. From there learners progress and accrue evidence of learning.

Current implementation snapshot

What is implemented today

Backend, domain, and product surfaces shipped as vertical slices. Each slice carries storage, domain commands, session-backed HTTP routes, backup/restore, and — where noted — a /learn product UI.

BYOA Operator Skills

Shared API-access and membership foundations, four curator job skills, student operation, and admin operation skills grounded in the OpenAPI contract.

Identity & Operations

First-Admin bootstrap, local-password login, server-side sessions, Admin identity ops, audit reads, health, diagnostics, request correlation, completion logs, backup & restore.

Program Shell & Membership

Program creation, Student self-join/leave/rejoin, invitation lifecycle, participant listing, Student removal, curator leave, Admin exceptional recovery/revocation, effective-participation checks, event reads.

Corpus Curation

Program sources, corpus candidates, acceptance/rejection, accepted corpus revisions, corpus event reads, and backup/restore support.

Topic / Concept / Material Navigation

Accepted topics, concepts, definitions, principles, material references, relationships, historical revisions, curator candidate routes, student-safe traversal, and a /learn navigation UI.

Material Content

Curator-only source raw content and a self-contained, immutable copy of accepted material content read by Students and Curators, a content_format vocabulary and size ceiling, curator-authorized hard delete, character-paginated read routes, a hasContent navigation signal, backup/restore validation, and a /learn content reader plus curator content form. Curator-owned licensing.

Accepted Checks & Criteria

Assessment criteria, open-answer checks, accepted revisions, and curator / student / admin read separation.

Open-Answer Workspace

Student submission, idempotency, owner-only attempt detail/list reads, evaluation status/evidence reads, evaluator orchestration, worker execution, and backup/restore support.

Quick Check

Session-backed routes, candidates, accepted revisions, protected answer keys, student-safe delivery projections, immutable attempts, matched evidence, and a /learn Curator/Student UI.

Learner-State Interpretation

Explicit target-link curation metadata, read-time owner-only progress and weak-area summaries, supporting-evidence target detail, and a /learn learner-state UI.

Readiness Checks

Topic- or named-period readiness definitions, evidence-backed explicit Student readiness attempts, idempotent retry, owner-only attempt reads, and a /learn readiness UI.

Coverage Gaps

Read-only Curator Workspace diagnostics over accepted corpus, deterministic draft_guidance reports, protected redaction, and a /learn filtering / drill-down UI.

LLM-Assisted Suggestions

Curator Workspace-owned deterministic-provider slice for redacted draft suggestions, origin inspection, accept/reject review, draft materialization without accepted-corpus promotion, and a /learn review UI.

Admin Board

A local operations board for bootstrap, sign in/out, Identity management, operational access inspection, audit inspection, and exceptional membership recovery/revocation.

Deferred: recommendation ranking and persisted mastery models still need separate specs; student- and curator-facing product UI beyond the shipped /learn slices is not yet implemented.
