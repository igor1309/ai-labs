# Руководство по созданию оптимального резюме Senior iOS Developer для hh.ru (Яндекс, СБЕР, Т-Банк)

---

## 1. Введение: Специфика hh.ru и ожидания от Senior iOS Developer в крупных компаниях

### 1.1 Особенности hh.ru для IT-специалистов
- **hh.ru** — крупнейшая площадка для поиска работы в России с интеграцией ATS (алгопоиск по ключевым словам).
- Резюме структурировано по секциям: опыт, образование, навыки, «Обо мне» и т.д.  
- Сильная конкуренция: на топовые вакансии подаются сотни резюме, и алгоритмы первыми видят только самые релевантные.

### 1.2 Ключевые ожидания от Senior iOS Developer

- **Техническое лидерство:** проектирование архитектуры для высоконагруженных, масштабируемых мобильных продуктов (миллионы MAU, отказоустойчивость, модульность).
- **Менторство:** развитие джунов/мидлов, участие в найме, проведение code review, организация обучающих сессий.
- **Влияние на продукт:** опыт работы в продуктовых командах, понимание бизнес-метрик, участие в стратегических решениях.
- **Кросс-функциональная коммуникация:** взаимодействие с аналитиками, дизайнерами, тестировщиками, менеджерами.
- **Улучшение процессов:** внедрение CI/CD, оптимизация процессов разработки, повышение культуры инженерного качества.

## 2. Официальные требования и возможности hh.ru

### 2.1 Обязательные и рекомендуемые поля резюме hh.ru

- **ФИО, Контакты** — стандарт.
- **Желаемая позиция** — “Senior iOS Developer / Ведущий iOS разработчик”.
- **Зарплатные ожидания** — по желанию (можно скрыть).
- **Опыт работы** — по шаблону hh.ru (последовательность, без пропусков).
- **Образование** — указывается в отдельном разделе.
- **Ключевые навыки** — отдельный теговый список (до 30 навыков).
- **Обо мне** — свободная форма, важна для самопрезентации.
- **Проекты** — опционально, есть возможность добавить ссылки на портфолио, GitHub, App Store.

### 2.2 Ограничения по объёму и форматированию

- Текстовые поля ограничены 2000 символами (примерно 300-350 слов) для большинства секций.
- Резюме должно быть в **plain text** — изображения, нестандартные символы и html-разметка игнорируются.
- Документ-прикрепление: PDF до 2МБ, но не читается ATS — основное внимание на текстовые поля в форме hh.ru.

### 2.3 Встроенные инструменты форматирования

- Используйте переносы строк, маркеры (“-”, “•”) для списков, чтобы повысить читабельность.
- Не используйте табуляцию, эмодзи, вложенные списки.

## 3. Оптимизация под алгоритмы hh.ru (ATS-friendly резюме)

### 3.1 Ключевые слова и фразы

#### 3.1.1 Технические ключевые слова
- **Языки:** Swift, Objective-C
- **Фреймворки:** UIKit, SwiftUI, CoreData, Realm, AVFoundation, Combine, RxSwift
- **Архитектура:** MVVM, MVP, VIPER, Clean Architecture, SOLID, Dependency Injection
- **Инструменты:** Xcode, Instruments, Fastlane, Jenkins, Git, CI/CD, CocoaPods, SPM
- **Качество:** Unit testing, UI testing, TDD, BDD, Snapshot testing, автоматизация тестирования
- **Производительность:** многопоточность (GCD, OperationQueue), оптимизация, профилирование, memory management
- **Безопасность:** Data protection, secure storage, keychain, app transport security

#### 3.1.2 Ключевые слова для сложных систем и бизнеса
- Высоконагруженные системы (highload, MAU >1M)
- Сложная бизнес-логика
- Интеграция с legacy, микросервисами
- Интеграция с аналитикой, push-уведомлениями, A/B тестами
- Масштабируемость, отказоустойчивость, мониторинг (observability)
- Code review, CI/CD, DevOps

#### 3.1.3 "Мягкие" и управленческие навыки
- Team lead, mentoring, onboarding, knowledge sharing
- Stakeholder management, кросс-функциональное взаимодействие
- Product thinking, agile/scrum/kanban, проактивность, аналитическое мышление, problem solving

### 3.2 Рекомендации по размещению и частоте ключевых слов

- **“Обо мне”, “Опыт работы” и “Навыки”** — ключевые слова должны быть распределены естественно по всем этим секциям.
- В каждом блоке — используйте вариации (например: “разработка с использованием Swift, UIKit и архитектурных паттернов MVVM/VIPER”).
- **Дублирование**: ATS hh.ru не наказывает за повтор — разумное упоминание ключевых фраз повышает видимость.

### 3.3 Ошибки, снижающие видимость для ATS

- Использование нестандартных символов, картинок, вложенных таблиц — **игнорируется** ATS.
- Отсутствие ключевых слов в описаниях или навыках.
- Описание обязанностей без указания достижений и масштабов (“занимался поддержкой приложения” — плохо, “Реализовал новый модуль X для аудитории в 5 млн пользователей” — хорошо).

## 4. Лучшие практики составления контента для крупных компаний

### 4.1 Раздел "Обо мне" / "Summary"

- Подчёркивает **Senior-уровень, техническое лидерство, релевантный опыт** в крупных проектах.
- Формулировки с цифрами, масштабом и спецификой:  
  > “Senior iOS Developer с 8+ годами опыта, экспертизой в архитектуре масштабируемых мобильных приложений для аудиторий 5M+, менторством и улучшением процессов разработки в продуктовых командах.”

### 4.2 Описание опыта работы

#### 4.2.1 Структура (STAR/CARL)

- **Situation/Context** — что за компания, что за проект
- **Task/Challenge** — ваша задача, вызов
- **Action** — ваши конкретные действия
- **Result/Outcome** — результат, эффект в цифрах

#### 4.2.2 Акценты
- **Масштаб:** количество пользователей, RPS, сложность инфраструктуры.
- **Влияние:** на продукт, бизнес-метрики, процессы (скорость релизов, снижение багов, рост Retention).
- **Роль:** техническое лидерство, архитектура, code review, найм, менторство.
- **Коллаборация:** с кем работали (PM, QA, аналитики, дизайн, бэкенд).
- **Достижения:** конкретные, количественно измеримые.

#### 4.2.3 Как это отразить  
- Не только "что делал", но "чего достиг", "что улучшил" (см. примеры ниже).

### 4.3 Ключевые навыки (раздел hh.ru)

- Используйте только **релевантные** и **распространённые** формулировки: “Swift”, “SwiftUI”, “CI/CD”, “Unit Testing”, “Code Review”, “Team leadership”.
- Не дублируйте экзотические технологии, если их нет в целевых вакансиях.
- Максимально используйте лимит тегов (до 30).

### 4.4 Проекты и портфолио

- Опишите **значимые проекты**: название, роль, стек, метрики (MAU, загрузки, рейтинг), задачи.
- Добавьте **ссылки**: GitHub (желательно — open source/пет-проекты с документацией, тестами), App Store (по возможности — со скриншотом рейтинга/загрузок).
- Пример:
  - `App Store: https://apps.apple.com/app/idxxxxxx (3.5M+ installs, 4.8★)`

### 4.5 Образование и курсы

- Важно для Senior — профильное высшее (желательно техническое: МФТИ, ВШЭ, МГУ и т.п.).
- Дополнительные курсы (Swift, архитектура, управление командой), международные сертификаты (Apple, Coursera, Udemy, Yandex Practicum).
- Не стоит перечислять базовые курсы или нерелевантные сертификаты.

### 4.6 Типичные ошибки

- Слишком общие/размытые формулировки (“Работал в команде”, “Писал код”).
- Перечисление всех технологий подряд (“знаю все”) — вызывает недоверие.
- Перебор с “мягкими” навыками без подтверждения кейсами.
- Нет конкретики: масштаб, результат, метрики.

## 5. Примеры фрагментов резюме

### 5.1 Пример раздела "Обо мне"

```markdown
Senior iOS Developer с более чем 8-летним опытом создания и масштабирования мобильных приложений для аудиторий 5 млн+ пользователей (B2C, финтех, e-commerce). Эксперт в архитектурном проектировании (MVVM, VIPER), менторстве, внедрении CI/CD, оптимизации производительности и развитии технической культуры команды. Привык брать ответственность за результат и бизнес-метрики.

5.2 Пример описания опыта работы

СберБанк Онлайн, Senior iOS Developer  
03.2021 – настоящее время

- Проектировал архитектуру нового модуля “Платежи”, рассчитанного на 15M+ активных пользователей (Swift, VIPER, Combine).
- Руководил командой из 4 разработчиков: проведение code review, менторство, найм новых сотрудников.
- Внедрил CI/CD (Jenkins + Fastlane), что сократило время релиза на 30% и снизило количество багов на проде на 40%.
- Инициировал оптимизацию CoreData-модуля, что ускорило загрузку данных на 25%.
- Взаимодействовал с продукт-менеджерами, QA и дизайнерами для запуска A/B-тестов и новых функций.

5.3 Пример заполнения раздела “Ключевые навыки”

Swift, SwiftUI, UIKit, CoreData, Realm, RxSwift, Combine, VIPER, MVVM, Unit Testing, TDD, CI/CD, Instruments, Xcode, Git, App Store, REST API, Agile, Team Leadership, Code Review, Performance Optimization, Problem Solving, Stakeholder Management, Mentoring, Product Mindset

6. Рекомендации по обновлению и поддержке резюме на hh.ru
	•	Обновлять раз в 1-2 месяца или при появлении значимых новых проектов/достижений (часто обновляемые резюме выше в поиске).
	•	Адаптировать “Обо мне” и сопроводительное письмо под конкретную компанию/вакансию: акцентировать нужные им компетенции.
	•	Следить за ключевыми словами — они должны совпадать с требованиями вакансии.
	•	В сопроводительном письме (или в самом резюме) выделить опыт в продуктовых/высоконагруженных проектах, достижения и роль в команде.
