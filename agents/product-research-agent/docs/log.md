# Log

## 2026-06-25

- Project established under `agents/product-research-agent/`: a draft **on-demand** OpenClaw agent that researches the current public state of a named company's product using evidence only, and returns a structured report as an attached Telegram file. Inverts the sibling-agent shape — no cron, no suppression gate, no heartbeat, no repository under review, no PRs; it runs solely when `@`-mentioned in its Telegram topic. The research standard is the repo's `prompts/product-research.md`, deployed into the workspace as `research-prompt.md` by CI and read fresh each run (single source of truth, never vendored here).
- Two feasibility questions resolved during intake (see `docs/intake.md`): **web research** uses the key-free **Codex Hosted Search** provider (`web_fetch` needs no key); **report delivery** is an agent-driven Telegram Bot API `sendDocument` via `exec`, because OpenClaw auto-disables the built-in message tool's file sending in forum topics (issue #31368) and it never sent generic documents anyway.
- Initial artifacts: `agent/agent.md` (system prompt), `README.md`, this log, `TODO.md`, and the CI sync workflow `.github/workflows/product-research-agent-sync.yml` (rsyncs `agent/**` → workspace, renames `agent.md`→`AGENTS.md`, and deploys `prompts/product-research.md` → `research-prompt.md`; triggers on changes to either). VPS wiring (agents.list entry, new topic + inbound binding, provider confirmation, delivery plumbing) and the `inventory` reflection are deferred deploy-time steps requiring SSH authorization — tracked in `TODO.md`.
