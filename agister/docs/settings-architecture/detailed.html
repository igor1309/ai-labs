Two layers

<repo>/.agister over ~/.agister

Every document below can live in the repo's .agister or in home, in the same layout.

  • A repo document replaces home's of the same kind and name, whole. Fields are never merged.
  • What exists is the union of both layers.
  • A YAML file holds exactly one YAML document. A second, after a ---, even an empty one, makes the file invalid; it is never left unread.
  • Documents name each other by name, not by path. So a process in home can name verify:repo or a prompt, and each repo supplies its own.
  • Home is $AGISTER_HOME, else ~/.agister. Agents cannot reach home; they can change a repo's .agister when they may write the repo.

Workflow

workflows/<name>.yaml · run with agister run <name>

Composes process calls into one run. Its settings fix what each call receives, never whoever starts it.

Holds

input.paramswhat the caller supplies, each with an optional default
input.valuesresolved once from the params, before any node starts; every fan-out node receives the same ones

Names

fan_out[].usesa process per node, all run at once over the same inputs
join.usesone process, given the fan-out nodes' results
input.values[].formthe brief forms a file value's text must have one of, checked before any node starts

Fan-out then join is the only shape today: no conditions, loops or graphs. The other workflow here is adr_review: one ADR review, then the judge.

Process

processes/<name>.yaml · run with agister run <name>

A named agent call: the task, what it takes in, and what must come out.

Holds

input.instructionthe task, in words
input.paramswhat the caller supplies
input.valuesthe inputs, each from a source: param, file, git.revision, git.merge_base, git.diff, git.changed_files, prompt
workspace.revisionthe value whose revision HEAD must be at; Agister does not move HEAD
workspace.cleantrue: a fresh call needs the worktree's content to be HEAD's; unset is false
tools.requirepermissions the call cannot do without
timeout, retry, …limit overrides; they may only narrow its policy

Names

usesits agent
policyits policy
output.schemaits output schema
verifyits verification, by name or held inline
input.values[].namea prompt, where the source is prompt
input.values[].formthe brief forms a file value's text must have one of
skillsits skills

A process with a verification, like this one, is still a process, not a workflow, and declares both workspace.revision and workspace.clean: true. Every call works in the caller's worktree, or the one --dir names: Agister makes no checkout and runs no setup.

Output schema

schemas/<name>.json

A JSON Schema the process's output must match.

A process names it as output.schema. Only JSON is supported.

Verification

verifies/<name>.yaml, or inline in the process

A command that must pass on the call's changes before the call completes.

Holds

commandwhat to run
timeouthow long it may take
max_attemptshow many turns the agent gets to make it pass
instructionwhat the agent is told when it fails

A process in home can name verify:repo, and each repo supplies its own verifies/repo.yaml. The command runs in the call's worktree.

Prompts

prompts/<name>.md

Plain text: the file is the value. A process takes one as an input, and may mark it optional; a missing optional prompt is left out.

Here: prompts/go-testing-seams.md and prompts/go-architecture.md.

Skills

skills/<name>/SKILL.md

One SKILL.md each, the folder's only file. A process names its skills and an agent names its own; the two lists are separate.

Names

skills (in a process)the skills this call needs for its task
skills (in an agent)the skills this agent always carries

Briefs

briefs/<name>.yaml

A brief's form: its parts in order and the template a caller copies. Agister checks a text's structure against it, never its meaning.

Holds

parts[].headingthe part's Markdown heading line, such as ## Intent; the part runs to the next heading of its level or above
parts[].requiredtrue: the text must have the part, once and not empty
parts[].readsthe exact text the part must read, as None. for Open
parts[].referencefile: the part's first back-quoted path, relative to the caller's directory, must exist
templatethe text a caller copies; its headings are the parts', each once and in order

A file value names the forms its text must have one of, as form: [goal, step]; one with no form is not checked. A call whose text has none of them is refused before it starts, exit 3, naming the input, each form and each wrong part. A form neither layer has makes what names it invalid. The examples ship goal and step.

Policy

policies/<name>.yaml

Execution defaults for the processes that name it. It speaks in permissions, never in a runtime's tools.

Holds

workspace.accessread-only or read-write
workspace.scopecandidate or repository
tools.allow, tools.denypermissions, from the service's vocabulary; denied wins over allowed
timeoutwithin the service's maximum
retry.max_attemptswithin the service's maximum
max_cost_usdwithin the service's maximum, if it sets one
stalewhen a silent or looping call is ended
stale.recover.max_resumeshow many recovery turns a call may take after a turn ended at a staleness limit: each resumes its session with what went stale; unset is 0, none
stale.recover.instructionwhat the agent is told with the evidence; a budget above 0 needs one

stale.recover only narrows: a process may lower max_resumes, down to 0, never raise it or set one its policy lacks. Its own instruction replaces the policy's. A budget above 0 needs a resumable agent on a runtime that resumes sessions.

Agent

agents/<name>.toml

A runtime profile: who does the work and how hard. It carries no task and no permissions.

Holds

model, model_familywhich model
effortone of the efforts its runtime mapping accepts
sessionfresh-only or resumable

Names

runtimeits runtime mapping
skillsits own skills

Runtime mapping

runtimes/<name>.yaml

One adapter, described in permissions: what each of its tools or sandbox modes lets an agent do.

Holds

adapterclaude-code, codex, pi or opencode
effortsthe efforts it accepts
primitives.selectone (sandbox modes) or any (tools)
primitives.items[].grantsthe permissions that primitive grants, from the service's vocabulary
primitives.items[].verifiedthe runtime versions it was observed on

Service

service.toml · one, with no name

Applies to every run. No document names it; policies and runtime mappings must keep its rules.

Holds

max_timeoutthe longest any call may run
max_attemptsthe most attempts any call may have
max_verify_attemptsthe most turns a verification may allow
max_cost_usdthe most any call may cost, if set
permissionsthe vocabulary: a policy uses only these, a runtime mapping grants only these
writingthe permissions that change the worktree; read-only access withholds them, and a call granted one holds the worktree alone
state_reachingpermissions that would reach Agister's own state; never granted

Blocks

blocks.yaml · one, repo only

What this repo refuses, even though home allows it.

Holds

blocks[].refagent:<name>, process:<name>, workflow:<name> or runtime:<name>
blocks[].reasonwhy, optional

How they compose

Limits only narrow

  • The service bounds the policy, the policy bounds the process, the process bounds the caller.
  • Asking for more than the level above allows is rejected, never quietly reduced.
  • A process narrows its policy's stale block too: a shorter limit, fewer stale.recover.max_resumes. The caller has no override for either.
  • A denied permission always wins over an allowed one.

Where permissions meet primitives

  • The call's effective permissions meet its agent's runtime mapping.
  • A primitive is granted only if everything it grants is allowed.
  • An allowed permission that no primitive provides is withheld. If the process requires it, the call is refused.
