Agister's settings architecture

Agister runs settings. Agents, processes, policies, output contracts, permission mappings, the permission vocabulary and service limits are all documents you change without rebuilding it. Code adds only the mechanisms settings cannot express: runtimes and input source kinds. Agister does not judge whether settings are right or safe.

Settings live in two folders with the same layout, the repo's and home's, and every reader takes both.

Two layers

Home is the global layer: ~/.agister, or wherever $AGISTER_HOME or --home points. The repo layer is the project's: the .agister folder at the root of its git repository. Outside a git repo, or without that folder, there is no repo layer.

A repo document replaces home's document of the same kind and name, whole: fields are not merged. Everything else comes from whichever layer has it. The repo's settings override home's unconditionally.

Home also holds live state that is not settings: runs, logs, locks, backups and the runtimes' sessions. Agents cannot reach home. They can change a repo's .agister when they may write the repo.

What a call does with them

A call reads every document once into an in-memory snapshot, checks it, and uses exactly what it checked. It records what it used, with digests: definitions, prompts, verification and skills.

A call depends on the service settings, its process and what that process uses. A broken document refuses only the calls that depend on it, naming the chain.

Install

agister install <dir> copies a settings folder, such as a repo's .agister, into home, document by document. It plans first: each document is created, replaced (with a diff) or unchanged, and documents only home has are kept. It checks the result in a staged copy, asks for a yes, backs up to backups/<stamp>/ and then writes. agister install --restore <stamp> undoes one install. Install never deletes, and it leaves out live state, skills and the repo's own blocks.

Pages

agister pages reads the settings files of both layers directly and read-only, and serves on loopback only. Its page combines the layers by the same rule, repo over home by kind and name, and marks each document repo, home or repo, replaces home.
