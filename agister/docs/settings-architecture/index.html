Agister · settings

Agister's settings architecture

Settings define the work; runs and calls are what executed it. Agister reads settings from up to three layers, composes each document field by field, and resolves a request into definitions core executes as a run, or into a refusal that names the chain at fault. Definitions live in settings, not in code; code adds only a runtime or an input source kind. Facts and sources are in notes.md; the decisions are ADR-001, ADR-002, ADR-003, ADR-008 and ADR-010 to ADR-013.

Three axes

Each thing has one name, on one axis. A definition is declared, resolved and planned; it never runs. An execution starts and ends; it is never declared.

Definitions, in settings:

  • workflow: work defined by inputs, an output contract and children, each a step or a workflow, composed by sequence, parallel, branch or bounded repetition; its bindings carry data into each child, and its conditions choose a branch, accept a result and end a repetition
  • step: a process bound to an agent, the one leaf; its inputs and output contract are its process's
  • process: what a step does: its prompt, inputs, environment, output schema, permissions and limits
  • agent: who does it: a runtime mapping, and the model, effort and skills its runtime takes; a bash agent names only the runtime
  • runtime mapping: what its runtime grants with no option, and its options with what each grants; bash offers none

Executions, in records; an execution names the definition it executes:

  • run: executes a workflow
  • call: executes a step
  • iteration: one execution of a repetition's body; every other child executes once, as a call (a step) or a run (a workflow)
  • turn: one exchange of a call with its runtime
  • session: the conversation a call held, on a runtime that keeps one

Machinery, in code, as settings meet it:

  • runtime: a program Agister drives through its wrapper; a runtime mapping names one
  • runtime facts: what a runtime can do; resolve refuses a step that needs what its runtime cannot do

ADR-012, terms; ADR-011, rules 2 to 4.

What a workflow names

Documents name each other by kind and name, fixed in settings, so they resolve without a run. A workflow composes steps and other workflows by sequence, parallel, branch or bounded repetition. A step binds a process to an agent; nothing but a step chooses an agent. Bash is a runtime, planned as any other: its agent names only the runtime, and its prompt is a script.

Each kind has its folder in a layer, and a document is the file named after it. Nothing but kind and name joins files across layers.

From files to definitions

Resolve takes a request: a document by kind and name (a workflow with its parameters), or a step, a process and an agent; a step requested alone resolves as a workflow of that one step, which is no document (ADR-013). Resolve is the gate before a run: what resolves may be run, what does not never reaches core and leaves no run. A problem in a document refuses only what depends on it; a problem of no document refuses every request; a refusal names the chain to the document at fault.
