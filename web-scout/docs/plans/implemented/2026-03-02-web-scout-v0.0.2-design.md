## Logging

### New spec rule (Rule 6)

> Writes a JSON line to `stderr` for each tool call: `{event, query, latencyMs, resultCount}` on success; `{event, query, latencyMs, error}` on failure. Suppressed when `LOG_LEVEL=silent`.

### Log shape

```json
{"event":"startup","searxngUrl":"http://localhost:8888","timeoutMs":5000,"maxResults":10}
{"event":"search","query":"rust async","latencyMs":312,"resultCount":5}
{"event":"search_error","query":"test","latencyMs":2,"error":"SearXNG down"}
```

### Configuration

- `LOG_LEVEL` env var: `info` (default — logs every call) or `silent` (no output)
- Added to the spec's Configuration section alongside existing env vars

### Implementation

One `process.stderr.write(JSON.stringify({...}) + "\n")` call in `index.js` after client creation (startup event). Two more in the existing try/catch in `mcp-server.js` (search and search_error events). No new dependency, no new module.

`stderr` is the correct fd — MCP stdio protocol owns `stdout`; Docker captures both streams independently.

## Docker

### `web-scout/Dockerfile`

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
COPY web-scout/package.json web-scout/
RUN npm ci --workspace=web-scout --omit=dev
COPY web-scout/src web-scout/src
ENTRYPOINT ["node", "web-scout/src/index.js"]
```

Built from repo root to include the npm workspace lockfile.

### `web-scout/docker-compose.yml`

```yaml
services:
  searxng:
    image: searxng/searxng:latest
    ports:
      - "127.0.0.1:8888:8080"

  web-scout-mcp:
    build: ..
    environment:
      SEARXNG_URL: http://searxng:8080
      LOG_LEVEL: info
    depends_on:
      - searxng
    stdin_open: true
```

`stdin_open: true` keeps the MCP stdio process alive when run in a container (prevents immediate exit).

### Env vars table

| Variable | Required | Default | Description |
|---|---|---|---|
| `SEARXNG_URL` | yes | — | SearXNG base URL |
| `SEARXNG_TIMEOUT_MS` | no | `5000` | HTTP request timeout |
| `SEARXNG_MAX_RESULTS` | no | `10` | Result cap |
| `LOG_LEVEL` | no | `info` | `info` or `silent` |
