# ADR-0001: VPS-first deployment for Nomos

Date: 2026-02-26  
Status: Accepted

## Context

Nomos is a solo-maintained AI sovereignty layer (vendor control, cost control, unified API, basic safeguards).  
Primary constraints: low operational overhead, predictable costs, and availability without relying on regional cloud services.

## Decision

Nomos will be deployed VPS-first as a single service behind TLS (reverse proxy), with local persistence (SQLite/Postgres).  
Client traffic will route: Client → Nomos (VPS) → LLM vendors.

## Rationale

- Predictable monthly cost and independence from managed cloud offerings
- Faster iteration and ownership of deployment pipeline
- Adequate availability for current usage patterns
- Latency tolerance is acceptable for target workloads

## Consequences

### Positive
- Simple operational model suitable for solo development
- Centralized control over vendor usage and budgets
- Portability across providers and hosting environments

### Negative / Trade-offs
- Higher end-to-end latency due to an additional network hop
- VPS region choice affects user and vendor RTT
- Scaling requires future design work (horizontal scaling, shared state)

## Mitigations

- Support streaming responses (SSE) to improve perceived latency
- Use strict timeouts and clear error reporting
- Choose VPS region aligned with primary users or vendor endpoints
- Keep service stateless where possible; store only governance state
