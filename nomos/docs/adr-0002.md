# ADR-0002: CI/CD Deployment via SSH

Status: Accepted; amended by ADR-0003
Scope: Nomos VPS deployment automation
Related: ADR-0001 (VPS-first deployment), ADR-0003 (staging environment), release-unit.yml

---

## 1. Executive Summary

Nomos deploys to its VPS automatically when a `nomos_v*` tag is pushed. The `release-unit.yml` workflow uses SSH jobs that copy source files, rebuild the Compose image, and restart the stack. ADR-0003 later split the original deploy flow into staging and production jobs.

---

## 2. Context

- Nomos runs on a single VPS (<VPS_IP>) as a Docker Compose stack.
- The initial deployment was performed manually (scp + docker build + docker compose up).
- Manual deploys are error-prone and unrepeatable.
- The trend-scout project on the same VPS already uses CI SSH deploy via `appleboy/ssh-action`.
- A Docker registry (GHCR) was considered but rejected: single deployment target, no multi-node scaling planned, and the image builds in under 10 seconds on the VPS.

---

## 3. Decision

Add Nomos deploy jobs to `release-unit.yml` that trigger only for Nomos releases. The jobs SSH into the VPS, sync source files from the repository, rebuild the Compose image, restart the Compose stack, and verify health endpoints.

---

## 4. Rules / Invariants

- The Nomos deploy jobs MUST run only after `core` (typecheck + tests) passes.
- The Nomos deploy jobs MUST be conditional on `needs.verify.outputs.basename == 'nomos'`.
- Deployment MUST use `appleboy/ssh-action` with Nomos VPS secrets (`NOMOS_VPS_HOST`, `NOMOS_VPS_USER`, `NOMOS_VPS_SSH_KEY`).
- The workflow and deploy scripts MUST:
  1. Stop the running stack (`docker compose down`).
  2. Copy or reuse updated source files (Dockerfile, package.json, package-lock.json, src/).
  3. Rebuild and start the Compose image (`docker compose up -d --build`).
  4. Wait for healthy status and verify the health endpoint returns `{"status":"ok"}`.
- The deploy script MUST NOT touch `.env`, `Caddyfile`, or `data/` — those are operator-managed on the VPS.
- GitHub secrets `NOMOS_VPS_HOST`, `NOMOS_VPS_USER`, `NOMOS_VPS_SSH_KEY` MUST be configured in the ai-labs repository.
- The `github-release` job MUST depend on Nomos deployment jobs (not just `core`) for Nomos releases, so a failed deploy blocks the GitHub Release.

---

## 5. Consequences

- Every Nomos tag push results in an automatic VPS deployment.
- No manual SSH or scp required for routine releases.
- Deploy failures are caught by CI and reported via Telegram.
- The VPS needs a clone or checkout of the repo for source access. Alternative: CI can scp files directly (simpler, no git on VPS for this purpose).
- Same VPS secrets are reusable if other projects deploy to the same host.

---

## 6. Non-Goals

- Docker registry (GHCR/Docker Hub) image publishing.
- Blue-green or rolling deployment.
- Multi-VPS or multi-region deployment.
- Database migration automation (SQLite schema changes are handled by the application on startup).
- Blue-green or rolling rollback beyond the current failed-deploy image snapshot.
